## 5.4 A1 的目标

A1 的任务不是证明模型预测得更准，而是直观回答一个问题：

> 对不同输入样本，GeoJet-TS 是否真的会改变 Gaussian primitives 的中心、宽度、显著性和激活数量？

它对应论文 5.4 中的 **Adaptive primitive geometry**。当前正文希望说明：

- (\mu_k) 会随主要时间结构的位置变化；
- (\sigma_k) 会随局部模式持续时间变化；
- (\alpha_k) 会区分不同 primitive 的贡献强弱；
- 不同样本的 active primitive count (K(x)) 不完全相同。

A1 本质上是一个**有明确选样协议的定性可视化实验**，不是相关性实验，也不是扰动实验。

------

# 一、实验输入如何选择

## 1. 使用哪个 checkpoint

建议主文 A1 固定使用：

- prediction horizon：(H=96)；
- 数据集：ETTh1、Ettm1、Weather、；
- 每个数据集使用对应的最佳验证 checkpoint；
- 只在测试集上提取结果。

完整的其他 horizon 可以放到附录。

------

## 2. 每个样本具体指什么

当前模型采用 channel-independent 处理，因此模型实际输入是一个单变量序列：

[
x\in\mathbb{R}^{512}.
]

所以一个 A1 展示单元应明确包含：

- dataset；
- test window index；
- channel index；
- prediction horizon；
- input sequence；
- 对应的 primitive 参数。

不能只记录“ETTm1 的第几个 batch”，否则以后很难复现。

------

## 3. 如何挑选样本

人工浏览挑最好看的，每个数据集可得到 3 个左右的样本。

主文空间有限时，可以只展示 4–6 个：

- ETTm1：中、高复杂度；
- Weather：低、高复杂度；
- Traffic：中、高复杂度。

其余放附录。

------

# 二、实验需要提取哪些内部变量

对每个被选中的输入序列，forward 时至少保存：

```text
dataset
horizon
sample_id
window_index
channel_id
input_sequence
complexity_kappa
mu
sigma
alpha
hard_gate
straight_through_gate
active_count
```

其中：

[
\mu_k\in[0,1]
]

是 normalized input coordinate；

[
\sigma_k>0
]

是 normalized width；

[
\alpha_k\in[0,1]
]

是 primitive saliency；

[
g_k\in{0,1}
]

是 hard active gate。

还建议保存：

[
\widetilde{\alpha}_k=\alpha_k g_k.
]

因为真正展示贡献时，单独画 (\alpha_k) 不够：一个 primitive 即使 (\alpha_k) 较大，只要 gate 为 0，它也不参与当前样本的 field。

## 坐标换算

画图前把 normalized coordinate 转换到输入序列的位置：

[
\mu_k^{\mathrm{idx}}=(L-1)\mu_k,
]

[
\sigma_k^{\mathrm{idx}}=(L-1)\sigma_k.
]

由于 (L=512)，中心位置位于 (0) 到 (511) 之间。

一个 primitive 的可视支持范围可以显示为：

[
[\mu_k^{\mathrm{idx}}-2\sigma_k^{\mathrm{idx}},
\ \mu_k^{\mathrm{idx}}+2\sigma_k^{\mathrm{idx}}].
]

超出输入边界的部分裁剪到 ([0,511])。

------

# 三、A1 应该画什么

建议每个样本画成上下两层。

## 上层：输入序列

绘制模型实际接收的归一化输入：

[
x_1,x_2,\ldots,x_{512}.
]

可以使用：

- 一条黑色或深色折线；
- 横轴为 input timestep；
- 纵轴为 normalized value。

应明确使用哪一种输入：

- RevIN 之前的 dataset-standardized input；
- 或 RevIN 之后、真正输入生成器的 sequence。

更建议画 **primitive generator 实际接收的 RevIN-normalized input**，因为 primitive 参数正是从这个输入生成的。

但图注必须写清楚，例如：

> The displayed sequences are the RevIN-normalized inputs used by the primitive generator.

如果担心审稿人难以理解，可以附录中同时提供原始标准化输入。

------

## 下层：active Gaussian supports

对每一个 active primitive (g_k=1)：

- 用圆点或竖线表示中心 (\mu_k)；
- 用水平线或半透明带表示 (\mu_k\pm2\sigma_k)；
- 用点大小、线宽或透明度表示 (\widetilde{\alpha}_k)；
- 在旁边标 primitive index (k)，但不要让文字太拥挤。

例如：

- 点的位置：(\mu_k^{\mathrm{idx}})；
- 水平线长度：(4\sigma_k^{\mathrm{idx}})；
- 点大小：
  [
  s_k=s_{\min}+
  (s_{\max}-s_{\min})
  \frac{\widetilde{\alpha}*k-\alpha*{\min}}
  {\alpha_{\max}-\alpha_{\min}+\epsilon}.
  ]

非激活 primitive 不建议出现在主图中。若要展示 routing，可以在附录中把 inactive primitive 画成浅灰色小点。

------

## 可选：绘制 scalar support response

还可以为每个 active primitive 绘制：

# [ r_k(t)

\widetilde{\alpha}_k
\exp\left(
-\frac{(t-\mu_k)^2}{2\sigma_k^2}
\right).
]

但这只是**标量 Gaussian support response**，不能称为完整 Gaussian temporal field。

因为完整 field 是：

[
F_x(t)=
\sum_k r_k(t)c_k,
]

其中 (c_k\in\mathbb{R}^d)，属于 latent space，不能直接与输入标量序列叠加比较。

所以图注应该写：

> Scalar support envelopes of the active Gaussian primitives.

不要写：

> Reconstruction of the input by the Gaussian field.

论文当前没有 reconstruction loss，这样写会导致概念错误。

------

# 四、A1 最适合展示什么现象

A1 最好覆盖以下三种情况。

## 情况 1：平滑、低复杂度输入

希望观察：

- active primitive 数较少；
- 部分 primitive 宽度较大；
- supports 覆盖较长、平滑的区域；
- 不需要很多窄 primitive。

但这只是希望观察到的行为，不应在实验前假定结果一定如此。

------

## 情况 2：包含尖峰或局部转折的高复杂度输入

希望观察：

- 在尖峰、转折附近出现较窄的 primitive；
- 中心位置靠近明显局部结构；
- active count 可能高于低复杂度样本；
- 不同 primitive 的 saliency 有明显差异。

------

## 情况 3：多个时间尺度并存

例如一段输入中既有缓慢趋势，也有局部振荡。

可能观察到：

- 宽 primitive 覆盖慢变化；
- 窄 primitive 对应局部变化；
- 不同尺度的 primitive 同时存在。

这类样本最能说明 sample-adaptive support geometry，而不是所有 supports 都有相似宽度。

------

# 五、A1 的结论强度需要控制

A1 是自然样本的定性分析，因此即使图很漂亮，也只能支持：

> Learned primitives exhibit sample-dependent locations, widths, saliencies, and routed counts, with representative supports qualitatively aligning with different temporal structures.

不宜仅凭 A1 就写：

> Primitive centers accurately track event locations.

也不宜写：

> Primitive widths correctly estimate event durations.

因为自然时间序列里没有明确的 event center 和 event duration ground truth。

若要支持更强结论，需要之前提到的 A2 受控 shift 和 dilation 实验。

------

# 六、实验应该输出数据，还是直接生成图片

最推荐的做法是：

> **实验负责输出完整原始数据，同时生成一版自动化检查图；最终论文图片由独立绘图脚本生成。**

不是二选一。

## 1. 推理脚本主要输出结构化数据

实验程序应首先保存内部变量，推荐格式：

- `.npz`：最简单，适合 NumPy 数组；
- `.pt`：如果直接保存 PyTorch tensor；
- `.parquet`：适合大量逐样本统计信息；
- `.json`：只适合元数据，不适合保存大量数组。

一个样本可保存成：

```python
{
    "dataset": "ETTm1",
    "horizon": 336,
    "window_index": 128,
    "channel_index": 3,
    "complexity": 14.27,
    "input": [...],             # [512]
    "mu": [...],                # [K]
    "sigma": [...],             # [K]
    "alpha": [...],             # [K]
    "hard_gate": [...],         # [K]
    "effective_alpha": [...],   # [K]
    "active_count": 5
}
```

最好再保存：

- model config；
- checkpoint path；
- random seed；
- data split；
- extraction date；
- git commit id；
- RevIN 前后输入的说明。

这样以后改画图风格时不需要重新跑模型。

------

## 2. 实验脚本应自动生成 diagnostic images

推理完成后，建议自动生成简单图片，用于检查：

- (\mu_k) 是否都在合法范围；
- (\sigma_k) 是否异常过大；
- gate 是否正确形成 ordered prefix；
- selected percentile sample 是否正确；
- active supports 是否真的对应当前样本；
- 样本和 checkpoint 是否错位。

这些图只用于 debug 和快速浏览，样式不必达到论文标准。

例如输出：

```text
outputs/
└── geometry_a1/
    ├── raw/
    │   ├── ETTm1_H336_all_samples.parquet
    │   ├── ETTm1_H336_selected_samples.npz
    │   ├── Weather_H336_selected_samples.npz
    │   └── Traffic_H336_selected_samples.npz
    ├── diagnostics/
    │   ├── ETTm1_low.png
    │   ├── ETTm1_mid.png
    │   ├── ETTm1_high.png
    │   └── ...
    └── manifest.json
```

------

## 3. 最终论文图由独立 plotting script 生成

推荐分成两个脚本：

```text
extract_geometry_a1.py
plot_geometry_a1.py
```

### `extract_geometry_a1.py`

负责：

- 加载 checkpoint；
- 遍历 clean test set；
- 计算 (\kappa(x))；
- 保存所有样本的 primitive 参数；
- 按 10%、50%、90% 分位选择样本；
- 输出 raw data；
- 输出简单 diagnostic images。

### `plot_geometry_a1.py`

负责：

- 读取已经保存的数据；

- 决定主文展示哪些样本；

- 统一字号、线宽、坐标轴；

- 生成 PDF、SVG 或高分辨率 PNG；

- 输出：

  ```text
  figures/geometry_a1.pdf
  ```

这样做比实验代码直接画最终图更好，原因是：

- 修改排版时不用重新推理；
- 选定不同 panel 时不用重新训练；
- 能保证主文和附录使用同一批原始结果；
- 更方便生成矢量 PDF；
- 数据和视觉设计彼此分离，复现性更高。
