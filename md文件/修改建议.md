Antigravity 的分析**大方向有价值，但其中第一点存在关键数学混淆，第二、三点也需要区分“设计取舍”和“真正缺陷”**。不建议原样采纳，比较合适的是：保留它对内容信号、边界效应和线性冗余的提醒，同时修正对尺度导数的理论定位。

## 一、对 Antigravity 分析的逐点判断

### 1. “尺度导数等价于二阶空间 Jet”：只在特定归一化下成立

对未归一化高斯

# [ g(u;\mu,\sigma)

\exp\left(
-\frac{(u-\mu)^2}{2\sigma^2}
\right),
]

有

# [ \frac{\partial g}{\partial\log\sigma}

\frac{(u-\mu)^2}{\sigma^2}g,
]

而

# [ \sigma^2\frac{\partial^2g}{\partial\mu^2}

\left(
\frac{(u-\mu)^2}{\sigma^2}-1
\right)g.
]

因此真正的关系是

# [ \boxed{ \frac{\partial g}{\partial\log\sigma}

\sigma^2\frac{\partial^2g}{\partial\mu^2}+g
}
]

而不是 Antigravity 给出的直接相等。

只有对连续、带 (1/\sigma) 归一化因子的 Gaussian density，

# [ \phi(u;\mu,\sigma)

\frac{1}{\sqrt{2\pi}\sigma}
\exp\left(
-\frac{(u-\mu)^2}{2\sigma^2}
\right),
]

才有经典尺度空间关系

# [ \frac{\partial\phi}{\partial\log\sigma}

\sigma^2\frac{\partial^2\phi}{\partial\mu^2}.
]

更重要的是，GeoJet 实际采用的是**有限 patch 网格上的离散归一化 Gaussian basis**，还包含数值稳定项，因此不能直接把连续热方程恒等式当作代码中的精确恒等式。当前论文明确使用归一化 canonical Gaussian bases，并对归一化 basis 使用解析中心导数。

理论定位应当是：

> (\partial\phi/\partial\log\sigma) 是 Gaussian 参数空间中沿 log-scale 方向的一阶切向量；其空间形状与二阶曲率响应密切相关。

它是：

- 对 ((\mu,\log\sigma)) 的**一阶多参数 Taylor 展开**；
- 不是对中心位移 (\Delta) 的二阶 Taylor 项；
- 也不应直接改名为“二阶中心 Jet”。

因此，最准确的名称是：

> **First-order Translation–Scale Affine Gaussian Jet**

或者：

> **First-order Affine Gaussian Jet with a curvature-related scale direction**

Antigravity 关于“不要把它宣称为精确的大尺度变形”的提醒是对的，但把它直接定性为“二阶空间 Jet”也过于绝对。

------

### 2. Scale cue 缺少 patch 内容：这个批评基本成立

原方案只从 Gaussian field 的中心分布和宽度中提取尺度统计，因此它描述的是：

> field 所暗示的局部 support spread。

它并不能直接知道 patch 内部是：

- 平滑趋势；
- 高频振荡；
- 尖峰；
- 局部冲击；
- 低频宽周期。

所以，如果新增机制的目标是**让 observation operator 根据真实局部内容改变分析尺度**，只使用 field spread 确实不够。

但是 Antigravity 提出的

[
\frac{\operatorname{Std}(p_j)}
{\operatorname{Mean}(|p_j|)+\epsilon}
]

不是最理想的 patch cue。它主要衡量幅值变化，不足以区分：

- 大幅但平滑的趋势；
- 小幅但高频的振荡。

更合适的是使用无参数、尺度相对稳定的局部粗糙度：

# [ E_j^{(0)}

\frac{1}{p}\sum_r p_{jr}^2,
]

# [ E_j^{(1)}

\frac{1}{p-1}
\sum_r
(p_{j,r+1}-p_{jr})^2,
]

# [ r_j^{\mathrm{patch}}

\log\left(
1+
\frac{E_j^{(1)}}
{E_j^{(0)}+\epsilon}
\right).
]

其中：

- (r_j^{\mathrm{patch}}) 较大：patch 更粗糙、包含较高频变化，倾向于使用较窄 support；
- (r_j^{\mathrm{patch}}) 较小：patch 更平滑，允许较宽 support。

这比标准差除以平均绝对值更贴近“局部分析尺度”。

------

### 3. 边界伪影：是一个真实风险

field spread 在时间轴边缘可能系统性偏小，因为：

- 边界外没有 primitive；
- responsibility 分布是单侧的；
- 有效参与的 primitive 数量可能更少。

原方案加入 (\sigma_k^2) 可以避免方差完全变为零，但不能彻底消除边界偏差。

建议增加两个可靠度因子：

#### Primitive diversity reliability

令

# [ \pi_{jk}

\frac{a_{jk}}
{\sum_\ell a_{j\ell}+\epsilon},
]

定义有效多样性：

# [ R_j^{\mathrm{div}}

\frac{
1-\sum_k\pi_{jk}^2
}{
1-1/K+\epsilon
}.
]

当只有一个 primitive 主导时，(R_j^{\mathrm{div}}) 接近零；当多个 primitive 共同贡献时，它较大。

#### Boundary reliability

# [ R_j^{\mathrm{edge}}

\operatorname{clip}
\left(
\frac{\min(t_j,1-t_j)}
{m_{\mathrm{edge}}},
0,1
\right).
]

最终 field-scale cue 使用

# [ R_j^{\mathrm{geom}}

R_j^{\mathrm{div}}
R_j^{\mathrm{edge}}.
]

边界或 primitive 支持不足时，field cue 自动衰减，而 patch-content cue 仍然可以工作。

------

### 4. detach 是设计选择，不是必然缺陷

当前 GeoJet 明确对 (\Delta_j) 和 (C_j) 使用 stop-gradient，目的是让 observation correction 读取 field geometry，但不反向驱动 field 改变自身几何。

因此，detach 带来的不是无意的“梯度断层”，而是有意维持：

[
\text{Gaussian field}
\longrightarrow
\text{observation pathway}
]

的单向条件接口。

如果允许 scale correction 反向更新 field centers，可能出现：

- field centers 为了降低 observation loss 人为扩大或缩小分散度；
- center relocation 和 scale cue 相互补偿；
- field representation 与 observation correction 的职责变得不可辨识；
- “center-only field geometry”主线被削弱。

当前 Gaussian field 的 center 是唯一样本相关几何参数，而 width 继续跨样本共享。

所以最终方案应当：

- 默认保留 detach；
- 增加 `scale_cue_detach` 开关；
- 将非 detach 版本作为消融，而不是默认实现。

------

### 5. 线性冗余风险：成立，但不是完全冗余

如果 (\rho_j) 是常数，那么

[
W_G\left(\rho q_j^{(\sigma)}\right)
]

确实只是 patch 的一个固定线性映射，理论上可能被

[
W_{\mathrm{base}}p_j
]

吸收。

但是当

[
\rho_j=\rho(x,j)
]

随样本和位置变化时，

[
\rho(x,j)
\left\langle p_j,\chi_m\right\rangle
]

是 field/content cue 与 patch response 的乘性耦合，不再等价于一个固定的 `nn.Linear(patch_len, d_model)`。

所以真正的问题不是“必然冗余”，而是：

> 如果 (\rho_j) 的变化很小、接近常数，新增尺度方向就会退化为容易被线性分支吸收的固定线性特征。

因此需要监测：

- `rho_std`；
- `rho_abs_mean`；
- scale term norm；
- scale term 与 center term 的 cosine similarity；
- Gaussian basis Gram matrix 的 condition number。

------

### 6. Dual-scale basis：适合作为备用方案，不应直接替代主方案

双尺度混合：

# [ q_j^{\mathrm{dual}}

(1-\lambda_j)q_j^{\mathrm{fine}}
+
\lambda_jq_j^{\mathrm{coarse}}
]

对较大尺度变化更稳定，但它更接近常规的 mixture-of-scales 或 multi-scale routing。

它的优点是：

- 不依赖局部 Taylor 近似；
- 容易训练；
- 能表达较大的尺度变化。

不足是：

- 创新性通常低于 affine parameter-space Jet；
- 需要额外计算一套 basis response；
- “Jet”理论联系会弱化；
- 容易被审稿人归类为普通多尺度门控。

因此最终路线应为：

1. 主方案：first-order translation–log-scale affine Jet；
2. 备用或对照：dual-scale mixture；
3. 只有在 derivative 版本明显失效时，再考虑将 dual-scale 作为正式模型。

------

# 二、最终推荐方案

最终模型使用：

# [ q_j^{\mathrm{aff}}

q_j^{(0)}
+
\Delta_jq_j^{(\mu)}
+
\rho_jq_j^{(\lambda)},
]

其中

# [ q_j^{(\lambda)}

\left\langle
p_j,
\frac{\partial\phi}
{\partial\log s}
\right\rangle.
]

尺度系数由 field geometry 与 patch roughness 共同决定：

# [ \rho_j

## \rho_{\max} \tanh \left( \gamma_g R_j^{\mathrm{geom}} z_j^{\mathrm{field}}

\gamma_p
z_j^{\mathrm{patch}}
\right).
]

语义为：

- field spread 较大：倾向于扩张 support；
- patch 粗糙度较大：倾向于收缩 support；
- 边界或 primitive diversity 不足：降低 field cue 的影响；
- (\rho_j) 始终有界；
- field cue 默认 detach；
- direct branch 不变。

------

# 三、可直接交给 Antigravity 的最终完整提示词

```text
角色与任务
==========

你需要在当前 GeoJet-TS PyTorch 仓库中实现一个可选的：

Content–Geometry Translation–Scale Affine Gaussian Jet

该机制用于扩展现有 observation pathway 中的 Gaussian Jet。
在任何代码修改之前，必须先完成仓库审计和数学核查。

不要把该机制描述为 field-width adaptation。
Gaussian field 的 primitive width 仍然是 sample-shared。
新增适应性只存在于 observation pathway 的 canonical Gaussian operator 中。


一、理论定位
============

当前 Jet：

q_jet_j = q_base_j + delta_j * q_center_j

扩展为：

q_affine_j =
    q_base_j
    + delta_j * q_center_j
    + rho_j * q_logscale_j

其中：

q_logscale_jm =
    <patch_j, d phi_m / d log(s_m)>

该机制是对 Gaussian 参数空间 (center, log-width) 的一阶多变量
Taylor expansion。

必须在代码注释和文档中准确说明：

1. d phi / d log(s) 是 log-scale 参数方向的一阶导数；
2. 它在空间形状上与二阶曲率响应相关；
3. 它不是中心位移 delta 的二阶 Taylor 项；
4. 不应称为精确的大尺度 dilation；
5. 它仅近似较小、有界的 local log-scale perturbation。

推荐名称：

First-order Translation–Scale Affine Gaussian Jet

禁止直接将其命名为：

- exact adaptive width
- true temporal dilation
- second-order center Taylor Jet
- sample-conditioned Gaussian field width


二、必须保持不变的 GeoJet 结构
============================

以下结构不得修改：

1. Gaussian field generator；
2. sample-conditioned field centers mu_k(x)；
3. sample-shared field widths sigma_k；
4. primitive activation；
5. field contents c_k(x)；
6. direct observation：

   b_j = W_base p_j

7. field response factor C_j；
8. positional cue delta_j；
9. residual fusion；
10. forecasting head；
11. channel-independent processing；
12. 仅使用 forecasting loss 的训练协议。

新增 scale term 只能影响 auxiliary Gaussian correction：

I_j =
    b_j
    + eta * C_j * W_G q_affine_j

不要修改 b_j。
不要让 scale cue 作用于 direct branch。
不要增加 sample-dependent residual fusion。
不要增加辅助监督。


三、Phase 0：仓库审计
====================

在修改任何代码之前，输出：

AFFINE_JET_AUDIT.md

必须包含：

1. Gaussian field 实现文件、类和函数；
2. mu_k(x)、sigma_k、g_k(x)、w_jk 的产生位置；
3. delta_j 和 C_j 的实现位置；
4. stop-gradient 的准确位置；
5. canonical Gaussian basis 的实际公式；
6. basis normalization 是：
   - sum/L1 normalization
   - L2 normalization
   - 其他形式
7. normalization denominator 中所有 epsilon 的准确位置；
8. canonical center 和 width 的参数化方式；
9. center derivative 的现有解析公式；
10. q_base、q_center、W_G、eta 的实现；
11. direct projection 和 residual fusion 的实现；
12. 所有相关张量 shape；
13. checkpoint loading 和配置系统；
14. 当前单元测试与训练入口；
15. 当前参数量、FLOPs、显存和推理速度测量方式。

必须对照实际代码，而不是仅根据论文猜测。

在审计完成前不要进行重构。


四、正确实现 normalized log-scale derivative
=============================================

禁止在 forward 中使用 torch.autograd.grad 动态计算 basis derivative。
必须使用解析公式。

设实际代码中的未归一化 basis 为：

raw_phi_mr = exp(f_mr)

归一化为：

phi_mr =
    raw_phi_mr /
    (sum_r raw_phi_mr + eps_norm)

令：

h_mr =
    d log(raw_phi_mr) / d log(s_m)

则 normalized basis 对 log-width 的精确导数为：

chi_mr =
    phi_mr * (
        h_mr
        - sum_r' phi_mr' * h_mr'
    )

注意：

1. h_mr 必须从仓库实际 Gaussian denominator 推导；
2. 如果 denominator 是 2*s^2 + eps_g，
   不允许直接使用忽略 eps_g 的近似公式；
3. 必须使用 quotient rule；
4. 不允许先计算 raw derivative 再单独 normalize derivative；
5. center derivative 和 log-scale derivative 应共用同一套
   normalization-Jacobian helper。

建议接口：

build_normalized_gaussian_jet_basis(...)

返回：

phi_base       # [M, p]
phi_center     # [M, p]
phi_logscale   # [M, p]

其中：

phi_center =
    d phi / d center

phi_logscale =
    d phi / d log(width)

实现公共函数：

normalize_with_derivative(
    raw_basis,
    raw_log_derivative,
    normalization_mode,
    eps
)

根据仓库实际 normalization 实现，不要增加无用模式。


五、Hybrid Scale Cue
====================

Scale cue 不得只依赖 Gaussian primitive 的中心分布。
它应由：

1. field-derived support spread；
2. patch-derived local roughness；

共同构成。


五.一 Field-derived spread
-------------------------

复用当前 positional cue 的 precision weights：

a_jk =
    w_jk * sigma_k^(-2)

pi_jk =
    a_jk /
    (sum_k a_jk + eps)

计算 weighted center：

mean_mu_j =
    sum_k pi_jk * mu_k

计算 between-center variance：

v_between_j =
    sum_k pi_jk * (mu_k - mean_mu_j)^2

计算 shared support baseline：

v_within_j =
    sum_k pi_jk * sigma_k^2

定义无量纲 field spread：

r_field_j =
    log1p(
        v_between_j /
        (v_within_j + eps)
    )

该量描述：

relative dispersion of locally responding field primitives

不要称其为 ground-truth temporal duration。


五.二 Primitive-diversity reliability
-------------------------------------

定义：

diversity_j =
    1 - sum_k pi_jk^2

若 K > 1：

R_div_j =
    clamp(
        diversity_j / (1 - 1/K + eps),
        0,
        1
    )

若 K == 1：

R_div_j = 0

当只有一个 primitive 主导时，field dispersion 不足以产生可靠的
sample-specific scale cue，因此降低 field cue 权重。


五.三 Boundary reliability
--------------------------

query coordinate t_j 位于 [0, 1]。

定义：

edge_distance_j =
    min(t_j, 1 - t_j)

edge_margin 默认设置为：

patch_len / max(input_len - 1, 1)

R_edge_j =
    clamp(
        edge_distance_j /
        (edge_margin + eps),
        0,
        1
    )

允许通过配置关闭 boundary attenuation，但默认开启。

field reliability：

R_geom_j =
    R_div_j * R_edge_j

C_j 仍然在最终 auxiliary correction 上起原有 attenuation 作用。
不要删除或重新解释 C_j。


五.四 Patch-content roughness
----------------------------

不要使用：

Std(patch) / Mean(abs(patch))

作为默认 cue。

使用无参数、幅值相对稳定的一阶差分能量：

E_signal_j =
    mean_r patch_jr^2

E_diff_j =
    mean_r (
        patch_j,r+1 - patch_j,r
    )^2

r_patch_j =
    log1p(
        E_diff_j /
        (E_signal_j + eps)
    )

语义：

- r_patch 较高：局部更粗糙、较高频，倾向于较窄 support；
- r_patch 较低：局部更平滑，允许较宽 support。

必须使用进入 direct observation branch 的同一 normalized patch。
不要重新读取未经相同预处理的原始序列。


五.五 Query-wise standardization
--------------------------------

分别在每个样本的 query 维度上标准化：

z_field =
    weighted_standardize(
        r_field,
        weight = detached(C) * R_geom
    )

z_patch =
    standardize(
        r_patch,
        dim = query_dim
    )

如果有效权重和过小，令 z_field = 0。
如果 query-wise std 小于 eps，令对应 z = 0。

随后：

z_field =
    clip(z_field, -z_max, z_max)

z_patch =
    clip(z_patch, -z_max, z_max)

默认：

scale_z_max = 3.0


五.六 Bounded hybrid log-scale shift
------------------------------------

使用两个非负全局增益：

gamma_field > 0
gamma_patch > 0

推荐使用 softplus 参数化。

默认有效初始值：

gamma_field_init = 0.05
gamma_patch_init = 0.05

定义：

rho_j =
    rho_max * tanh(
        gamma_field
        * R_geom_j
        * z_field_j

        -

        gamma_patch
        * z_patch_j
    )

其中减号表达：

patch roughness 增大时，倾向于使用更窄的 local Gaussian support。

默认：

scale_rho_max = 0.25

必须满足：

abs(rho_j) <= scale_rho_max

实际一阶近似对应的尺度倍率为：

exp(rho_j)

不要在代码中直接构造 query-specific effective width，
也不要生成 [B, P, M, patch_len] 的 effective basis。


六、Stop-gradient 策略
=====================

默认设置：

scale_cue_detach = true

默认情况下执行：

z_field = z_field.detach()
R_geom = R_geom.detach()
z_patch = z_patch.detach()

注意：

1. rho 不得 detach；
2. gamma_field 和 gamma_patch 必须获得梯度；
3. field centers 和 field widths 不应通过 scale cue 接收梯度；
4. 现有 delta 和 C 的 detach 行为不得改变。

提供消融配置：

scale_cue_detach = false

非 detach 版本仅用于实验，不作为默认主模型。

需要在文档中明确解释：

stop-gradient maintains a one-way conditioning interface from
the Gaussian field to the observation pathway.


七、Affine Jet forward
=====================

计算：

q_base_jm =
    <patch_j, phi_base_m>

q_center_jm =
    <patch_j, phi_center_m>

q_logscale_jm =
    <patch_j, phi_logscale_m>

然后：

q_affine =
    q_base
    + delta * q_center

if use_scale_jet:
    q_affine =
        q_affine
        + rho * q_logscale

保持现有：

observation =
    direct_observation
    + eta
    * confidence
    * gaussian_projection(q_affine)

禁止新增：

- W_scale
- eta_scale
- scale MLP
- sample-dependent fusion gate
- auxiliary scale loss
- field-width generator

第一版必须复用现有 W_G。

若 rho_std 长期接近零，必须报告该机制可能退化为固定线性映射。

十、可选 residualized scale basis
================================

仅作为诊断性消融提供：

scale_basis_mode = per_basis_residual

对每个 basis m，将 phi_logscale_m 投影到：

span(
    phi_base_m,
    phi_center_m
)

并取残差：

phi_logscale_residual_m =
    phi_logscale_m
    - Projection_span(
        phi_logscale_m
    )

要求：

1. 使用稳定 QR 或 least-squares；
2. 不在每次 forward 重复计算；
3. 明确标记该版本不再是精确的 log-scale derivative；
4. 不得作为默认模型；
5. 只用于检验线性共线性是否导致 scale direction 失效。


十一、数值稳定性
===============

以下运算使用 FP32，即使模型处于 FP16/BF16：

2. normalization denominator；
3. derivative basis；
4. first and second moments；
5. variance；
6. log1p；
7. weighted mean/std；

随后再转换回模型 dtype。

- one active primitive；
- identical centers；
- constant patch；
- all-zero patch；
- nearly zero signal energy；
- boundary query；
- very narrow basis width；
- FP16；
```
